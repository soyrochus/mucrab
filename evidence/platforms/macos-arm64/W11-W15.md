## Issues exposed and verification conditions

- Search traversal now normalizes Mac filenames to NFC, matching pane listings;
  raw filesystem paths remain intact. A new Mac regression verifies matching and
  containing-folder activation. Synthetic predicate inputs stay exact.
- The supplied mount-boundary fixture now uses its canonical path, matching
  `/var` → `/private/var` resolution. Parallel search-worker fixtures also include
  an atomic counter because Mac clock values collided between two tests.
- Access times were observed changing after chmod outside the metadata plan;
  the responsible host process or mechanism was not identified. Exact automated
  metadata checks therefore run on a dedicated
  APFS test volume mounted **noatime**; explicit timestamp writes are still
  asserted. Native edits on the regular user volume have separate read-back.
  This does not promise immunity to another process accessing a file afterward.
- APFS rejects invalid UTF-8 filename creation. That existing real-server case
  remains executed on Linux; it is not counted as exercised on Mac. The rest of
  the real SFTP failure test runs, including timeout/cancel/uncertain publication.
- Native Keychain acceptance creates, reads, updates and deletes a unique test
  account under the app service. It never replaces an existing account, changes
  defaults or locks the user's Keychain. Isolation is per item, not a separate
  Keychain database. Missing-item reads and idempotent deletion also pass.
- Test-only dependencies are Paramiko 4.0.0 and Pillow 13.0.0 in an isolated venv.
  No production dependency pins changed.

## Repeating the automated run

Use Python 3.12+ and a venv containing Paramiko 4.0.0 and Pillow. Create/attach a
fresh disposable APFS image at a new path. The runner requires a genuinely
different device. On this host, mount the disposable test volume with `noatime`
before exact metadata checks:

```sh
mount -u -o noatime "$PWD/artifacts/macos-verification/w11-w15-mount"
PATH="$PWD/artifacts/runtime/w15-venv/bin:/opt/homebrew/bin:$PATH" \
  python -B tools/verify_w11_w15_macos.py \
  --cross-device-root artifacts/macos-verification/w11-w15-mount
```

Loopback sockets, native permission semantics, LaunchServices and Keychain require
access outside a restricted sandbox. Keep the actual failed sandbox attempts;
do not treat a socket/Keychain denial as a passing service test. The runner keeps
unique raw runs and writes Mac comparisons beside Linux evidence. The W15 service
server and native-input server use separate fresh fixtures because service tests
mutate their data. Never point those tests at personal servers or key files.
